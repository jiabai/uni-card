# 0004 输入页「下一步」直接出图：主流程不经预览页

V3.8 及以前的核心流程是「三段三页」：选择页 → 输入页 → 预览页 → 分享图片页，预览页是主流程必经环节，归档也在「进入预览页」时触发。V3.9 决策推翻该结构：**输入页点「下一步」直接生成分享图，中间不经预览页**——预览页退出主流程，仅保留供二期素材库「用这条分享」入口复用。

## 决策内容

1. **主流程压缩为「两段两页」**：选择页 → 输入页 →（下一步出图）→ 分享图片页；预览页不再是必经页。
2. **归档触发点由「进入预览页」改为「出图成功」**（修订 ADR 0001）——出图失败不归档，不沉淀无效内容。身份绑定规则（ADR 0002）不变，仅触发时机前移。
3. **抽取共享导出模块 `src/lib/card-export.js`**：从 `preview.vue` 抽出「取隐藏画布 → 绘制 → 落临时文件」逻辑，对外 `exportCardImage(instance, templateId, fields)`，输入页与预览页共用，避免两套导出代码。overflow（画布高度超 4096 上限）以 `err.overflow = true` 抛出，由调用方转提示。
4. **输入页与预览页各自挂隐藏导出画布**（`#exportCanvas`，`type="2d"`），统一 `position:fixed; left:-9999px` 移出可视区（不能用 `display:none`）。

## Consequences

- 术语「三段三页」（V3.8 及以前称谓）废止，改为「两段两页」；`CONTEXT.md` 的「卡片预览页」「归档」「输入页」三条术语同步修订。
- 预览页 `pages/preview` 退出主流程，当前保留（index 与 edit 均不再跳转它），供二期素材库「用这条分享」入口复用；是否彻底删除待定。
- 输入页 `onShareTap` 由「跳预览页」改为「校验 → showLoading → exportCardImage → upsertMemo → navigateTo share」。
- 两个真机约束随之固化：`getCurrentInstance()` 须在 setup 作用域捕获后传入导出模块；隐藏 canvas 不能用 `display:none`。二者已沉淀进 AGENTS.md。
- 与 ADR 0003「选模板与填内容分两页」共同构成当前「两段两页」结构，每次写作比三段三页少一次页面跳转。
