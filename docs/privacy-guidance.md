## 一、结论

**只需声明 1 项：使用你的相册（仅写入）权限。**

这是本项目唯一调用到的隐私接口。声明项越少，被驳回的概率越低。

## 三、需声明项（可直接复制）

**处理的信息**：使用你的相册（仅写入）权限

**用途描述**（推荐，逐字复制）：

```
用于将用户生成的分享卡片图片保存到用户手机相册
```

**为什么这样写**：这是官方驳回率最高的一项。「仅写入」意味着只有保存能力，**没有读取、上传、编辑、发布能力**。描述必须落到「保存」这个动作上。

**禁止出现的写法**（会直接驳回）：

- ❌ 「用于上传图片、编辑个人信息」
- ❌ 「用于发布内容、扫码」
- ❌ 「用于提升用户体验」
- ❌ 「为了收集信息而收集信息」
- ❌ 留空或填写「使用」「开发」等含糊词

## 四、明确不要勾选的项

后台会列出全部信息类型供自主勾选，**除第三项外一律不勾**。特别容易误勾的两项：

| 信息类型 | 对应接口 | 本项目是否使用 |
|---|---|---|
| 收集你选中的照片或视频信息 | `wx.chooseImage` / `chooseMedia` / `chooseVideo` | 否（只读不写，本项目只写不读） |
| 收集你的手机号 | `<button open-type="getPhoneNumber">` | 否（本项目无 `open-type`） |

其余（位置、地址、发票、微信运动、车牌、文件、麦克风、摄像头、蓝牙、通讯录、日历、传感器、剪切板）全部未使用，**一律不勾**。

多声明会被判定为「收集信息与功能不匹配」，同样导致驳回。

## 五、其他必填字段

**开发者对信息的存储**（复制）：

```
开发者不会将你的信息上传至服务器。用户输入的文字内容与生成的卡片历史仅保存在用户设备本地，用户卸载小程序后自动清除。
```

**联系方式**：填一个可用的邮箱（如 `你的邮箱@qq.com`），用于用户行使查阅、复制、更正、删除等权利。这一项必填且需真实可达。

**信息的使用规则 / 信息对外提供**：沿用后台默认模板即可，本项目无第三方插件、无第三方服务商代开发，无需额外填写。

**存储期限**：如界面要求填写，填「仅存储于用户设备本地，卸载小程序即清除」。

## 六、填报位置与流程

1. 开发者工具上传代码后，在 mp 后台「版本管理」提交审核。
2. 在**提审页面底部**找到「完善用户隐私保护指引」入口并填写。
3. 微信会「根据小程序版本隐私接口调用情况展示必填项」——上传代码后系统会自动把「相册（仅写入）」标为必填并高亮，按上文文案填即可。
4. 随代码审核一并审核，通过后随发布上线生效。

⚠️ **注意**：小程序未发布上线前，mp 后台「设置 → 服务内容声明 → 用户隐私保护指引」是改不了的。首次必须在提审页面底部填报，不要去后台找入口。

## 七、驳回风险自查表

提审前逐条确认：

- [ ] 只勾选了「使用你的相册（仅写入）权限」一项
- [ ] 用途描述含「保存」字样，与「仅写入」匹配
- [ ] 用途描述非空、非「使用/开发」等含糊词
- [ ] 用途描述未出现「上传/编辑/发布/扫码」
- [ ] 联系方式邮箱真实可用
- [ ] 未在 `app.json` 配置 `"__usePrivacyCheck__": false`（有此配置会导致隐私校验失效）

## 八、配套文案：备案「服务内容描述」

备案流程中需填写小程序的服务内容描述，建议（复制并按需微调）：

```
本小程序是一款文字转图片卡片的轻量工具。用户选择一个卡片模板并输入想说的话，小程序在本地生成一张配图卡片，用户可将其保存到手机相册，或直接发送给微信好友、群聊与朋友圈。小程序不收集任何用户个人信息，不进行任何网络通信，所有内容仅保存在用户设备本地。
```

要点：强调「本地生成」「不收集个人信息」「无网络通信」，与代码实际情况一致，便于备案初审快速通过。

## 九、服务类目建议

主体为个人主体时可选类目有限，建议在「工具」大类下选择与图片处理相关的子类。最终以 mp 后台实际可选列表为准，选择与上述服务描述最贴近的一项即可，避免选择需要前置审批的类目（教育、医疗、金融、新闻出版等）。

## 十、后续维护

若后续版本新增了隐私接口（如读取相册、获取位置），**必须先更新本指引再发版**，否则新接口调用会直接失败，报错形如 `saveImageToPhotosAlbum:fail privacy permission is not authorized`（`errno: 104`）。
